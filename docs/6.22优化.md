# 6.22 研讨室与评审流程优化

## 一、重新评审文档状态恢复

**问题**：用户点击"重新评审"进入 ReviewCreatePage 后，如果未发起评审就离开，文档状态卡在 `'ready'`，不恢复原状态。

**方案**：
- 新增 `reviewStartedRef`，`handleStart` 时设为 `true`
- `useEffect` cleanup 中检查：未发起评审则恢复文档原状态（`'reviewed'`）或移除临时补回的文档
- `addDocument` 路径的 cleanup 调用 `removeDocument`

**文件**：`frontend/src/pages/reviews/ReviewCreatePage.tsx`

---

## 二、推荐角色置顶显示

**问题**：推荐创建的临时角色与常规角色混排显示，不易区分。

**方案**：
- `visibleAgents` 拆分为 `visibleTempAgents` + `visibleRegularAgents`
- 列表顶部新增"推荐角色"区块（amber 色系，`WandSparkles` 图标，"推荐" badge）
- 推荐角色卡片使用 amber 边框/背景，选中态 `border-amber-500 bg-amber-50`
- `hasRecommended` 门控：未点击"推荐创建"时不显示该区块
- `selectAllAgents` / 空态 / 全选按钮同步适配

**文件**：`frontend/src/pages/reviews/ReviewCreatePage.tsx`

---

## 三、收藏内容来源角色记录

**问题**：`ReviewBookmark` 无来源角色信息，无法知道收藏的内容是哪个角色提出的。

**方案**：
- `ReviewBookmark` 新增 `source_agent_id?: string`（争议用逗号分隔多 ID）
- 只存 ID 不存 name，显示时实时反查（支持角色重命名/同名）
- `BookmarkableParagraph` 新增 `sourceAgentIds` prop

**各收藏点处理**：

| 收藏点 | sourceAgentIds 来源 |
|---|---|
| 单角色观点/亮点/维度/引用 | `item.agent_id`（直接取） |
| 优化建议/引用/收益 | `review.agents.find(a => a.name === suggestion.source_agent)?.id`（反查） |
| 争议 | `opinions.map(op => review.agents.find(a => a.name === op.agent_name)?.id).join(',')` |
| 总体诊断/痛点/亮点/共识 | 不传（聚合内容无单一来源） |

**文件**：`frontend/src/types/index.ts`、`frontend/src/components/ui/BookmarkableParagraph.tsx`、`frontend/src/pages/reviews/ReviewDetailPage.tsx`

## 四、必须参与角色锁定

**问题**：用户可取消收藏内容来源角色的参与，导致议题提出者不在研讨中。

**方案**：
- `ChatRoomConfigModal` 新增 `requiredAgentIds` prop
- `ReviewDetailPage` 从未讨论的收藏中提取所有 `source_agent_id` 计算 `requiredAgentIds`
- "必须参与"区块置顶显示（amber 色系，`Lock` 图标）
- `toggleAgentSelect` 对 requiredAgent 拦截：`toast('info', '本次议题有该角色提出内容，需要该角色参与。')`
- 角色已删除时 inline 提示："以下内容来源角色已被删除，可从回收站恢复：XX"
- `selectedAgentIds` 初始化时自动包含 requiredAgentIds
- 必须参与的角色不在下方"我的角色"列表重复出现

**文件**：`frontend/src/components/ui/ChatRoomConfigModal.tsx`、`frontend/src/pages/reviews/ReviewDetailPage.tsx`

## 七、恢复 @点名功能

**问题**：之前为修复 agent 名字出现在讨论内容中的 bug，完全禁止了 `@角色名`，导致角色无法互相点名。

**方案**：

| 改动 | 说明 |
|---|---|
| 上下文格式 | `[角色名]:` → `角色名说：`（自然语言，LLM 不会模仿方括号前缀） |
| teammates | 恢复"或点名互动" |
| 规则 3 | 拆分：禁止 `[角色名]` 前缀，允许 `@角色名` 点名 |
| responseGuide | 重编号 3./4. → 4./5.（消除编号冲突） |

**文件**：`frontend/src/pages/chat/ChatRoomPage.tsx`

## 八、修复角色话术雷同

**问题**：身份验证违规 → 重写仍失败 → `createIdentitySafeFallbackReply` 输出硬编码模板，只有 `focus` 变化，导致不同问题的话术几乎一样。

**方案**：两轮 LLM 重写

**第一次重写**：
- system prompt 加入 `agent.system_prompt`，让重写感知角色人设

**第二次重写**（第一次仍失败时）：
- 包含违规详情（`violations[].message`）
- 包含禁止词列表（`profile.forbiddenClaims`）
- 包含 `agent.system_prompt` + 角色名 + 议题上下文
- 明确身份类型约束

**完整流程**：
```
初始回复 → 验证
  ├── 通过 → 使用
  └── 需重写 → 重写#1（含 system_prompt）
        ├── 通过 → 使用
        └── 需重写 → 重写#2（含违规详情+禁止词+system_prompt）
              ├── 非空 → 使用（不验证）
              └── 空/失败 → 硬编码 fallback 兜底
```

**文件**：`frontend/src/pages/chat/ChatRoomPage.tsx`

## 九、议题点击对应角色回复

**问题**：点击议题时不指定来源角色，无法让提出该议题的角色优先回复。

**方案**：

### 数据流打通
```
评审收藏（source_agent_id）→ agendaBookmarks → pendingTopics（source_agent_id）→ 点击议题 → 对应角色发言
```

### 具体改动

| 改动 | 说明 |
|---|---|
| `ChatAgendaItem` 新增 `source_agent_id` | 争议用逗号分隔多 ID |
| `agendaBookmarks` 结构化传递 | 完整格式 `{icon} {category}：{fullContent}` + `source_agent_id` |
| `handleTopicClick` | 从 `topic.source_agent_id` 解析角色 |
| 单角色议题 | `targetAgent` = 该角色，走现有逻辑 |
| 多角色议题（争议） | `requiredSpeakers` = 所有角色，每个都发言，不受 maxTurns 限制 |
| 无来源角色议题 | 走通用逻辑 |
| 角色已被删除 | `participants.find()` 返回 undefined，被 filter 掉 |

### `buildDiscussionTurns` 多角色分支
```typescript
if (requiredSpeakers && requiredSpeakers.length > 1) {
  return requiredSpeakers.map((agent, index) => {
    const turn: DiscussionTurn = {
      agent,
      intent: (index === 0 ? 'open' : 'support'),
      focus: topicText,
      isUserDirected: true,
    }
    return turn
  })
}
```

**文件**：`frontend/src/types/index.ts`、`frontend/src/components/ui/ChatRoomConfigModal.tsx`、`frontend/src/pages/reviews/ReviewDetailPage.tsx`、`frontend/src/pages/chat/ChatRoomPage.tsx`
