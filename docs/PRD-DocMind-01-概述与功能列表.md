## 1. 产品概述

### 1.1 产品定位

DocMind 是一款 **多角色 AI Agent 文档评审平台**，用户上传文档后，可选择或创建不同身份的 AI Agent（如老师、学生、技术专家、产品经理等）组成评审团队，获得多视角评价与优化建议。用户还可将 Agent 添加至聊天室进行深度辩论，通过角色碰撞发现文档盲区、激发优化方向。

### 1.2 核心价值

| 层次 | 价值描述 |
|------|---------|
| **认知差价值** | 弥补单一视角的局限性，让文档同时接受多个"立场"的审视 |
| **效率价值** | 将多角色评审从高成本的人工协作，变为零等待的 AI 即时体验 |
| **对话碰撞价值** | 评价不是终点，通过对抗性辩论帮用户做出更明智的决策 |

### 1.3 产品愿景

> **让每一份文档都能被"认真对待"——模拟一个微型评审委员会，让不同立场的智慧同时作用于你的文档。**

## 2. 目标用户

### 2.1 核心用户画像

| 用户类型 | 场景 | 痛点 | 使用方式 |
|---------|------|------|---------|
| **产品经理** | PRD/需求文档评审 | 找不到足够多的人来交叉 review | 选择「技术+设计+商业」多角色评审 |
| **技术写作者** | 技术文档/API文档评审 | 不确定读者能否看懂 | 创建「初级开发者」Agent 来验证可读性 |
| **学生/研究者** | 论文/报告评审 | 导师反馈慢，同学反馈浅 | 选择「导师+同行+外行」角色审阅 |
| **内容创作者** | 文案/策划方案评审 | 只能自己反复看，看不出问题 | 用多个视角检验表达力和说服力 |
| **团队负责人** | 方案/提案评审 | 团队评审会成本高、效率低 | 预评审，提前暴露问题，再开真人会议 |

## 3. 核心用户旅程

```
用户旅程主线：

注册/登录 → 创建/选择Agent → 上传文档 → 发起评审 → 查看多角色评价
    │                                          │
    │              ┌───────────────────────────┘
    │              ▼
    │         对评价满意？
    │         ├── 是 → 导出/采纳建议 → 结束
    │         └── 否 → 进入聊天室 → 与Agent辩论 → 优化文档 → 重新评审
    │                      │
    │                      ▼
    │               辩论中需要新视角？
    │               └── 邀请新Agent加入 → 继续讨论
    │
    └── 首次使用 → 引导创建第一个自定义Agent
```

### 关键路径（Happy Path）

1. **用户注册** → 进入新手引导
2. **创建第一个 Agent** → AI 对话引导，3 轮内生成可用角色
3. **上传文档** → 拖拽上传，自动解析内容结构
4. **发起评审** → 选择 2-3 个 Agent，一键开始
5. **查看报告** → 评分 + 多角色观点 + 共识/争议 + 优化建议
6. **深度讨论** → 对争议点进入聊天室辩论
7. **优化文档** → 采纳建议后重新评审，持续迭代

## 6. 关键设计原则

| 原则 | 说明 |
|------|------|
| 🎭 **角色一致性** | Agent 在任何场景都严格遵循设定的身份和性格，不"出戏" |
| 💬 **对话真实感** | Agent 间辩论要有"碰撞感"，不是各说各话 |
| ⚡ **即时反馈** | 评审结果流式输出，不让用户干等 |
| 🎯 **建议可执行** | 每条建议必须具体到"改哪里、怎么改" |
| 🔧 **用户可控** | 用户可随时调整 Agent、中断辩论、重新评审 |
