# DocMind PRD — 非功能需求、里程碑与风险

---

## 8. 非功能需求

### 8.1 性能需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 页面首屏加载 | < 2 秒 | 正常网络环境 |
| 文档上传响应 | < 3 秒 | 不含解析时间 |
| 文档解析时间 | < 10 秒 | 5000 字以内文档 |
| 单 Agent 评审 | < 15 秒 | 5000 字文档 + 单 Agent |
| 5 Agent 并行评审 | < 30 秒 | 5000 字文档 + 5 Agent |
| 聊天室 Agent 回复 | < 5 秒 | 首字响应时间 |
| 流式输出延迟 | < 500ms | 用户发送到看到第一个字 |
| 并发用户支持 | 100 人 | MVP 阶段 |
| API 响应时间 | < 200ms | 非 AI 调用的普通接口 |

### 8.2 安全需求

| 需求 | 说明 |
|------|------|
| **用户认证** | 支持 JWT Token 认证，Token 有效期 7 天 |
| **数据隔离** | 用户间的文档、Agent、评审数据完全隔离 |
| **文件安全** | 上传文件存储在隔离的 OSS/S3 存储桶中 |
| **输入过滤** | 所有用户输入进行 XSS/SQL 注入过滤 |
| **API 限流** | 单用户 API 调用频率限制：60 次/分钟 |
| **AI 输出安全** | Agent 回复需经过内容安全过滤 |
| **HTTPS** | 全站 HTTPS 加密传输 |
| **日志审计** | 关键操作（上传、评审、删除）记录审计日志 |

### 8.3 可用性需求

| 需求 | 说明 |
|------|------|
| **系统可用性** | 99.5%（MVP 阶段） |
| **错误恢复** | 评审中断后可恢复，不丢失已完成的部分 |
| **数据备份** | 用户文档和 Agent 数据每日备份 |
| **降级策略** | AI 服务不可用时提示用户稍后重试，不影响其他功能 |

### 8.4 兼容性需求

| 平台 | 要求 |
|------|------|
| **浏览器** | Chrome 90+、Edge 90+、Firefox 90+、Safari 15+ |
| **设备** | PC 端为主（MVP），平板可浏览 |
| **分辨率** | 最小支持 1280×720 |
| **移动端** | MVP 阶段不做专项适配，v1.0 计划支持 |

### 8.5 可扩展性需求

| 需求 | 说明 |
|------|------|
| **AI 模型可替换** | 架构上支持切换不同的 LLM 提供商 |
| **文档格式可扩展** | 解析层抽象，便于后续支持更多格式 |
| **Agent 参数可扩展** | Agent 数据模型预留扩展字段 |
| **插件化评审** | 评审策略可通过配置调整，无需改代码 |

## 9. 里程碑计划

### 9.1 整体时间线

```
2026 年路线图：

├── v0.1 MVP ──────── 第 1-6 周
│   文档上传 + Agent模板 + 多角色评审 + 评审报告
│
├── v0.2 ──────────── 第 7-10 周
│   对话式创建Agent + 多Agent聊天室 + 对比视图
│
├── v0.3 ──────────── 第 11-13 周
│   同事Agent推荐 + Agent间互动 + 辩论总结
│
└── v1.0 ──────────── 第 14-16 周
    社区共享 + 报告导出 + 优化打磨
```

### 9.2 各里程碑详细规划

#### MVP（v0.1）— 第 1-6 周

| 周 | 任务 | 交付物 |
|:--:|------|--------|
| 1-2 | 基础架构搭建 + 用户系统 + 文档上传与解析 | 可登录 + 可上传文档 |
| 3 | 预设 Agent 模板库 + Agent CRUD | 8 个预设 Agent 可用 |
| 4-5 | 多角色并行评审引擎 + 流式输出 | 可发起评审并获得结果 |
| 6 | 评审报告展示 + 新手引导 + Bug 修复 | 完整可用的 MVP |

**MVP 验收标准**：
- [ ] 新用户可在 5 分钟内完成：注册 → 创建Agent → 上传文档 → 获得评审结果
- [ ] 预设 8 个 Agent 模板，覆盖 4 种以上评审场景
- [ ] 最多 5 个 Agent 并行评审，30 秒内完成

#### v0.2 — 第 7-10 周

| 周 | 任务 | 交付物 |
|:--:|------|--------|
| 7-8 | 对话式创建 Agent（含 AI 引导） | 可通过对话创建自定义 Agent |
| 9-10 | 多 Agent 聊天室 + 从评审进入 | 可在聊天室中与 Agent 辩论 |

#### v0.3 — 第 11-13 周

| 周 | 任务 | 交付物 |
|:--:|------|--------|
| 11 | 同事 Agent 推荐 + Agent 调教 | 智能推荐互补角色 |
| 12 | Agent 间自动互动 + 引用文档 | Agent 可自主辩论 |
| 13 | 辩论总结 + 建议采纳追踪 | 完整的评审→辩论→优化闭环 |

#### v1.0 — 第 14-16 周

| 周 | 任务 | 交付物 |
|:--:|------|--------|
| 14 | Agent 社区共享 + 评审报告导出 | 可分享/使用社区 Agent |
| 15 | 版本管理 + 性能优化 | 稳定可靠的完整产品 |
| 16 | 移动端适配 + 最终打磨 | 可发布的 v1.0 |

## 10. 风险与应对

### 10.1 技术风险

| 风险 | 影响 | 概率 | 应对策略 |
|------|:----:|:----:|---------|
| **AI 输出质量不稳定** | Agent 评审质量参差不齐 | 高 | 1. 精心设计 system prompt<br>2. 引入评审模板约束输出格式<br>3. 少量样本测试调优 |
| **AI 响应延迟** | 用户等待时间过长 | 中 | 1. 流式输出降低感知等待<br>2. 多 Agent 并行调用<br>3. 缓存常见评审模式 |
| **AI 成本过高** | 运营成本不可控 | 中 | 1. 设置每次评审 token 上限<br>2. 分级调用（不同场景用不同模型）<br>3. 监控每日调用量 |
| **角色一致性差** | Agent "出戏"影响体验 | 中 | 1. system prompt 强化角色约束<br>2. 每次对话携带角色上下文<br>3. 定期人工抽检 |

### 10.2 产品风险

| 风险 | 影响 | 概率 | 应对策略 |
|------|:----:|:----:|---------|
| **新用户不知如何创建 Agent** | 用户流失 | 高 | 1. 优质预设模板降低门槛<br>2. 新手引导强制体验<br>3. 系统推荐 Agent 组合 |
| **评审建议不够具体** | 用户觉得没价值 | 中 | 1. 要求 Agent 必须引用原文<br>2. 建议必须包含"改哪里+怎么改"<br>3. 反馈机制持续优化 |
| **聊天室辩论枯燥** | Agent 各说各话 | 中 | 1. 设计 Agent 间互动触发机制<br>2. 强制回应对立观点<br>3. 适时总结避免重复 |

### 10.3 运营风险

| 风险 | 影响 | 概率 | 应对策略 |
|------|:----:|:----:|---------|
| **冷启动困难** | 社区 Agent 库为空 | 高 | MVP 不依赖社区，靠预设模板<br>种子用户贡献优质 Agent |
| **用户留存低** | 用完即走 | 中 | Agent 创建投入增加粘性<br>评审历史形成数据资产 |
| **不当内容** | Agent 生成有害内容 | 低 | 内容安全过滤<br>举报机制 |

## 11. 成功指标（North Star Metrics）

### 11.1 MVP 阶段核心指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| **周活跃用户（WAU）** | 每周至少完成 1 次评审的用户 | 100 人 |
| **评审完成率** | 发起评审后完整查看报告的比例 | > 80% |
| **Agent 创建率** | 至少创建 1 个自定义 Agent 的用户比例 | > 40% |
| **聊天室使用率** | 评审后进入聊天室的用户比例 | > 25% |
| **NPS** | 用户净推荐值 | > 30 |

### 11.2 增长阶段核心指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| **MAU** | 月活跃用户 | 5,000 人 |
| **单用户平均评审次数** | 月均 | > 5 次 |
| **社区 Agent 使用率** | 使用他人共享 Agent 的比例 | > 20% |
| **付费转化率** | 免费转付费用户比例 | > 5% |
