# DocMind v0.1 优化记录

> 整理日期：2026-06-04

## Phase 1：导航 + 首页重构

### 1.1 顶部导航精简

**问题**：原导航项过多，用户聚焦困难。

**改动**：

| 原来 | 现在 |
|------|------|
| 首页 / 文档中心 / 评审大厅 / 角色管理 / 研讨室 / 设置 | 首页 / 评审大厅 / 评审团 / 研讨室 |

- 移除独立的"文档中心"和"角色管理"入口，整合到首页和评审流程中
- 设置保留在用户下拉菜单中

**文件**：`frontend/src/components/layout/Header.tsx`

### 1.2 DashboardPage 重构

**问题**：首页功能分散，流程不连贯。

**改动**：

- **线性流程布局**：上传文档 → 选择角色 → 发起评审，一目了然
- **内嵌上传区**：拖拽上传直接在首页完成，无需跳转到文档中心
- **多文件支持**：支持同时上传多个文件，批量解析
- **解析完成自动跳转**：最后一个文件解析完成后自动跳转到发起评审页面，URL 携带 `from=dashboard`
- **文档清理机制**：上传的文档 ID 存入 `sessionStorage('dashboard_uploaded_doc_ids')`，离开首页时注册到 `pendingCleanupDocIds`，放弃评审时自动删除

**文件**：`frontend/src/pages/dashboard/DashboardPage.tsx`

### 1.3 sessionStorage 清理桥梁

- DashboardPage 上传完成后将文档 ID 写入 `sessionStorage`
- ReviewCreatePage 入口处读取 sessionStorage，注册到 `pendingCleanupDocIds`
- Header 导航和浏览器后退时触发 `clearPendingCleanup()` 删除未完成评审的文档

**文件**：`frontend/src/pages/dashboard/DashboardPage.tsx`、`frontend/src/pages/reviews/ReviewCreatePage.tsx`、`frontend/src/components/layout/Header.tsx`

## Phase 2：ReviewCreatePage 优化

### 2.1 上下文感知返回按钮

**问题**：发起评审页的返回按钮始终链接到评审大厅，但用户可能从首页进入。

**改动**：

| 来源 | 返回行为 |
|------|----------|
| `from=dashboard` | 删除文档 + 导航回首页（按钮文本"返回首页重新上传"） |
| `from=reviews` | `clearPendingCleanup()` + 导航回评审大厅 |
| 其他 | `<Link to="/reviews">` 普通链接回评审大厅 |

**文件**：`frontend/src/pages/reviews/ReviewCreatePage.tsx`

### 2.2 预设模板直接可选

**问题**：原流程需要先"添加"模板到我的角色才能在评审中使用，步骤繁琐。

**改动**：

- 预设模板作为独立卡片直接可选中，无需先添加到"我的角色"
- `selectedAgentIds` 支持 `tpl-{templateId}` 前缀格式，区分模板 ID 和角色 ID
- 评审执行时，模板 ID 前缀会被剥离，用 `buildSystemPrompt(tpl)` 生成对应 system prompt

**文件**：`frontend/src/pages/reviews/ReviewCreatePage.tsx`

### 2.3 预设模板选择卡

- 卡片显示"官方"Badge + 角色分类（教师/学生/家长）
- 点击即选中/取消，不跳转到详情

### 2.4 useRef 泛型修复

- 第 516 行 `useRef` 缺少泛型参数 `>`，已修复

### 2.5 "新增角色"按钮移至卡片标题栏

- 原来内联的弹窗改为使用统一的 `UnifiedAddModal` 组件
- "新增角色"按钮从卡片内容区移至卡片标题栏右侧

### 2.6 移除"默认已选中"开关

- 新增角色/模板不再自动勾选到评审角色列表

### 2.7 文档清理机制完善（Dashboard 流程）

**`documentStore` 新增**：

| 方法 | 作用 |
|------|------|
| `registerCleanupDocs(ids)` | 标记待清理文档 ID |
| `clearPendingCleanup()` | 执行删除所有待清理文档 |
| `cancelCleanup()` | 清空待清理列表但不删除（评审开始后调用） |

**`ReviewCreatePage` 入口清理**：
- `useEffect` 中读取 `sessionStorage('dashboard_uploaded_doc_ids')` 注册清理
- `handleStart` 中调用 `cancelCleanup()` 保护文档

**`Header` 触发清理**：
- `handleNavClick` 和 `popstate` 事件中调用 `clearPendingDocsIfNeeded()`
- 同时清除 `sessionStorage('dashboard_uploaded_doc_ids')`

**文件**：`frontend/src/stores/documentStore.ts`、`frontend/src/pages/reviews/ReviewCreatePage.tsx`、`frontend/src/components/layout/Header.tsx`

### 2.8 文档 reviewed 状态

- 评审开始后将文档状态设为 `'reviewed'`
- ReviewCreatePage 筛选文档时只显示 `status === 'ready'` 的文档
- 对比评审模式下，两份文档都设为 `'reviewed'`

**文件**：`frontend/src/types/index.ts`（`Document.status` 新增 `'reviewed'`）、`frontend/src/pages/reviews/ReviewCreatePage.tsx`

### 4.3 取消评审功能修复

**原问题**：

1. 点击"取消评审"只有 `abort()` + toast，无页面跳转或状态恢复
2. 异步流程继续走到 `setPhase('done')`，显示完成页面
3. 无用的 `in_progress` 评审记录残留在 store

**修复**：

取消按钮行为：

| 步骤 | 操作 |
|------|------|
| 1 | `abortRef.current?.abort()` 中止 LLM 请求 |
| 2 | 清除所有定时器 |
| 3 | `cancelledRef.current = true` 标记取消 |
| 4 | `removeReview(currentReviewId)` 删除已创建的评审记录 |
| 5 | `updateDocument(docId, { status: 'ready' })` 恢复文档状态 |
| 6 | `registerCleanupDocs([docId])` 重新注册文档清理 |
| 7 | `setPhase('config')` 回到配置页 |

异步流程保护：
- `handleStart` 中两个异步路径（对比评审 + 单人评审），在 `await Promise.all(...)` 之后检查 `cancelledRef.current`，若为 `true` 则 `return`，不更新评审为 completed

**reviewStore 新增**：

```ts
removeReview: (id: string) => void  // 按 id 删除评审记录
```

**文件**：`frontend/src/pages/reviews/ReviewCreatePage.tsx`、`frontend/src/stores/reviewStore.ts`

### 4.4 从评审大厅上传的文档清理

**文件**：`frontend/src/pages/reviews/ReviewCreatePage.tsx`

### 4.5 评审报告页 → 文档详情页

## 关键设计决策

| 决策 | 说明 |
|------|------|
| 预设角色独立于"我的角色" | 预设模板不复制为自定义角色，通过 `tpl-` 前缀在评审中直接选择 |
| `tpl-` 前缀格式 | `selectedAgentIds` 中用 `tpl-{templateId}` 区分模板 ID 和角色 ID |
| `visibleInReview` 字段 | Agent 和 AgentTemplate 都支持该字段，控制评审选择中的可见性 |
| `templateVisibility` store | 替代原来的 `hiddenTemplateIds`，用 `Record<string, boolean>` 管理 |
| 文档清理机制 | `pendingCleanupDocIds` 延迟删除模式，避免 React StrictMode 下 `useEffect` cleanup 误删 |
| `reviewed` 文档状态 | 评审开始后文档标记为 `reviewed`，不再出现在发起评审的文档选择中 |
| 取消评审 = 回到配置页 | `setPhase('config')` + 重新注册清理 + 恢复文档状态，而非跳转完成页 |
| DocumentUploadModal 统一 | 文档中心和评审大厅共用同一组件，通过 `onUploaded` 回调区分后续跳转 |
| 上下文感知返回 | `from` URL 参数驱动返回按钮行为，保证用户始终回到正确的来源页 |
