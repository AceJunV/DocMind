# 6.17 优化 — 推荐创建临时评委功能

## 概述
在发起评审页面新增「推荐创建」功能，系统读取文档内容并深度创建 2 个临时评审角色（课程专家 + 教师）。评审团页面新增「临时评委」栏目，回收站增强展示信息。

## 涉及文件

| 文件 | 改动 |
|------|------|
| `frontend/src/types/index.ts` | Agent 类型扩展 |
| `frontend/src/stores/agentStore.ts` | Store 层：tempAgents 管理 |
| `frontend/src/pages/reviews/ReviewCreatePage.tsx` | 推荐创建按钮 + 弹窗集成 |
| `frontend/src/pages/agents/AgentListPage.tsx` | 临时评委栏目 + 回收站增强 |

## 执行顺序

### Task 1 — Agent 类型扩展
**文件：** `frontend/src/types/index.ts`
- `Agent.source` 联合类型新增 `'temp'`
- `Agent` 新增可选字段：
  - `reviewed_doc_id?: string`
  - `reviewed_doc_title?: string`

### Task 2 — Agent Store 扩展
**文件：** `frontend/src/stores/agentStore.ts`
新增状态与动作：

| 项目 | 说明 |
|------|------|
| `tempAgents: Agent[]` | 临时评委列表，最多 2 个 |
| `setTempAgents(agents)` | 设置临时评委，旧的自动移入回收站（由 `trashedAgents` 管理）|
| `regularizeTempAgent(id)` | 转正：tempAgents 中移除 → agents 中新增（`source: 'custom'`，保留 `reviewed_doc_title`）|
| 持久化 | `tempAgents` 加入 `partialize` |
| `restoreAgent` 修改 | 若恢复的是 temp 角色，自动转正（`source: 'custom'`）移入 agents |

### Task 3 — 推荐生成 Prompt
**位置：** `AgentListPage.tsx`（与 `DEEP_CREATION_PROMPT` 同区域）
- 新建 prompt 常量 `RECOMMEND_CREATION_PROMPT`
- 输入：文档标题 + 文档正文摘要
- 指令：基于文档内容生成 2 个临时评审角色（定位为课程专家和教师，名称自动生成）
- 输出格式：`{"agents": [{...}, {...}]}`
- 每个 Agent 包含：name, avatar, tagline, color, category, personality, expertise, behavior, system_prompt

### Task 4 — parseAgentsJSON 辅助函数
**位置：** `AgentListPage.tsx`（`parseAgentJSON` 旁）
- 解析 `{"agents": [{...}, {...}]}` 格式
- 返回 `Agent[]`，校验每个 Agent 必须有 `name` 和 `personality`

### Task 5 — 推荐创建弹窗 Modal 组件
**组件名：** `RecommendCreateModal`
**位置：** `ReviewCreatePage.tsx`
- 居中 Modal
- 展示 2 张完整角色卡片（每张包含：头像/名称/标语/性格参数进度条/专长标签/说话风格/口头禅/来源 + 关联文档标记）
- 三个按钮：
  - **重新**：重新调 LLM 生成，刷新卡片
  - **X**：关闭弹窗，不保存
  - **确认**：调 `setTempAgents` 保存到 store，关闭弹窗
- 加载中状态（LLM 调用时）
- 错误处理（LLM 失败时显示错误 + 重试）

### Task 6 — ReviewCreatePage 新增推荐创建按钮
**位置：** 全选按钮左侧
- `disabled` 条件：`!selectedDoc`（hover 提示"请先选择文档"）
- 点击流程：
  1. 读取 `selectedDoc.raw_content`
  2. 调 `chatCompletion`（使用 `RECOMMEND_CREATION_PROMPT`）
  3. `parseAgentsJSON` 解析结果
  4. 打开 `RecommendCreateModal` 展示
  5. 确认后 `setTempAgents` 保存
- 样式：与「新增角色」按钮相同风格（`bg-primary-600` 填充按钮）

### Task 7 — 评审团页临时评委栏目
**位置：** `AgentListPage.tsx`，「我的角色」下方
- 从 `store.tempAgents` 读取数据
- 栏目标题：`临时评委 ({count}/2)`
- 卡片展示：
  - AgentManageCard 相同布局
  - 额外标记：来源标记"临时" + 关联的文档标题（`reviewed_doc_title`）
  - 【转正】按钮 → `regularizeTempAgent(id)`
  - 【移除】按钮 → `removeAgent(id)`（移入回收站）

### Task 8 — 回收站增强
**位置：** `AgentListPage.tsx`，回收站 tab
- 每行现有字段（头像 + 名称 + 标语）不变
- 新增列：
  - `创建时间`：`created_at` 格式化为 `YYYY-MM-DD HH:mm`
  - `评审文档`：`reviewed_doc_title`，无则为 `-`
- `restoreAgent` 逻辑（Task 2 已修改）：temp 角色恢复时自动转正为 `custom`

### Task 9 — 验证编译
- `npm run build` 确认无新增错误
- 冒烟测试：手动验证各交互路径

## 关键行为规则

| 场景 | 行为 |
|------|------|
| 无文档时点击推荐创建 | 按钮 disabled，hover 提示 |
| 再次点击推荐创建 | 旧 temps 移入回收站 → 新 temps 替换 |
| 转正 | tempAgents 移除 → agents 新增（source: custom）|
| 回收站恢复 temp | 自动转正为 custom |
| 临时评委最多 | 2 个 |
| 推荐创建后 | 临时评委出现在角色选择列表中，默认不勾选 |

## 后续补充优化

### 6.17-1 — creation_reason 字段（卡片显示生成理由）

- **需求**：用户看到推荐角色卡片时不清楚为什么生成这两个角色，需要针对文档内容简短说明
- **修改**：
  - `types/index.ts` — `Agent` 新增 `creation_reason?: string`
  - `AgentListPage.tsx` — prompt JSON schema 中新增 `creation_reason`，要求 LLM 输出基于文档内容的评审切入点说明
  - `ReviewCreatePage.tsx` — `RecommendCreateModal` 每张卡片顶部增加高亮区块（琥珀色背景 + 灯泡图标）展示 `creation_reason`

### 6.17-2 — 临时角色不参与评审的 Bug 修复

- **需求**：选中临时评委后发起评审，临时评委不执行评审
- **根因**：`selectedAgentEntries` 只查 `agents`（永久角色），不查 `tempAgents`
- **修改**：
  - `ReviewCreatePage.tsx:551` — `agents.find(...) \|\| tempAgents.find(...)`
  - `ReviewCreatePage.tsx:558` — useMemo 依赖数组添加 `tempAgents`
  - `agentStore.ts:349-352` — `incrementUsage` 同时更新 `tempAgents`

### 6.17-3 — 文档含 Markdown 图片语法导致 LLM 报错

- **需求**：上传的 `.md` 文件含有 `![image](image.png)` 语法时，LLM 报 "Cannot read image.png"
- **根因**：`parseMd()` 原样返回 Markdown 文本，图片语法未被过滤，LLM 端将 `![]()` 视为图片输入请求
- **修改**：
  - `documentParser.ts:352-355` — `parseMd()` 中 `raw_content` 剥离 `!\[.*?\]\(.*?\)`
  - `reviewEngine.ts:468` — `executeTeachingEvalReview()` 防御性追加 `.replace(/!\[.*?\]\(.*?\)/g, '')`

### 6.17-4 — 重新评审文档丢失问题

- **需求**：评审详情页点击"重新评审"后，发起评审页面没有文档
- **根因**：`documentStore` 中已无该文档（状态为 `'reviewed'` 被过滤），`documents.find(...)` 找不到
- **修改**：
  - `ReviewDetailPage.tsx:676-688` — "重新评审"按钮改为 onClick handler，导航前从 `review.document` 补回 `documentStore`
  - `ReviewCreatePage.tsx:549-562` — useEffect 兜底：文档在 `allDocuments` 但状态非 `'ready'` 时 `updateDocument(id, { status: 'ready' })`；完全不存在时从评审记录 `addDocument`

### 6.17-5 — 文档详情页去掉操作和新建评审

- **需求**：文档详情页移除"操作"卡片（发起评审 + 删除文档）和"新建评审"按钮
- **修改**：
  - `DocumentDetailPage.tsx:165-201` — 删除整个"操作" Card 区块
  - `DocumentDetailPage.tsx:280-287` — 删除"评审历史" CardHeader 中的"新建评审"按钮和副标题

### 6.17-6 — 研讨室角色选择加入临时评委

- **需求**：进入研讨室时，角色选择列表需要包含临时评委
- **修改**（`ChatRoomConfigModal.tsx`）：
  - 新增 `tempAgents` store 选择器
  - `visibleAgents` 合并 `[...agents, ...tempAgents]`
  - `handleCreateRoom` 中 `participants` 解析追加 `?? tempAgents.find(...)` 兜底

### 6.17-7 — 新增角色 tab 切换保留表单状态

- **需求**：在预设/自定义/AI生成/深度创角之间切换 tab 时，已输入的内容不应清空
- **根因**：`{tab === 'custom' && <CustomAddModal />}` 条件渲染导致 React 卸载子组件，`useState` 丢失
- **修改**（`AgentListPage.tsx:1441-1452`）：
  - 用 `<div className={tab !== 'x' ? 'hidden' : ''}>` 包裹子组件，始终挂载在 DOM 中，仅切换 display
  - 关闭 modal 时由父组件统一卸载清理
