# DocMind 产品架构

**版本**: v1.0.0-teaching | **日期**: 2026-04-22 | **主版本**: v0.2.0

---

## 1. 产品概述

### 1.1 定位

DocMind 是一款多角色 AI Agent 文档评审平台。用户上传文档后，创建或选择不同身份的 AI Agent 组成评审团队，获得多视角评价与优化建议；还可将 Agent 添加至聊天室进行深度辩论。

**[教研版 v1.0.0-teaching]** 在主版本基础上，面向教研老师的教研案评审场景深度定制：预设教研老师、学生、家长三类角色（共 12 个），从课程设计、知识链、教学目标、课程重点、课程难点、学习梯度六个维度进行专业评审。部署地址：`http://123.207.2.148/teaching/`

### 1.2 目标用户

| 用户类型 | 核心场景 | 版本 |
|---------|---------|------|
| 产品经理 | PRD / 需求文档的交叉评审 | 主版本 |
| 技术写作者 | 技术文档可读性验证 | 主版本 |
| 学生/研究者 | 论文多角色审阅 | 主版本 |
| 内容创作者 | 文案说服力检验 | 主版本 |
| 团队负责人 | 方案预评审、降低会议成本 | 主版本 |
| **教研老师** | **教研案多角色评审、教学设计优化** | **教研版** |
| **教研组长** | **评审团队教研案质量把控** | **教研版** |

### 1.3 核心价值主张

1. **多视角放大器**：弥补单人审视的认知盲区
2. **零等待评审**：AI 即时扮演多种角色，无需组织真人
3. **对抗性对话**：通过角色碰撞暴露问题、激发优化方向

## 2. 功能架构

### 2.1 模块划分

```
DocMind 平台
│
├── 文档中心
│   ├── 文档上传（拖拽/点击，PDF/Word/MD/TXT）
│   ├── 文档解析（自动提取标题、段落、关键词、摘要）
│   ├── 文档列表（搜索、排序、状态筛选）
│   ├── 文档详情（文档信息 + 操作 + 评审历史，无内容预览）
│   └── 文档导出（评审报告 → PDF/Markdown）
│
├── Agent 工坊
│   ├── 预设模板库（8 个预设角色，横向滑动浏览，点击查看详情弹窗，一键添加）
│   ├── 引导式对话创建（AI 分步引导：行业→性格→关注点→生成）
│   ├── 随机生成（"抽卡"体验，随机组合角色属性）
│   ├── 我的 Agent 库（查看/编辑/删除→移入回收站）
│   ├── 模板隐藏（不需要的预设模板可隐藏，回收站可恢复）
│   ├── 回收站（已删除的 Agent + 已隐藏的模板，支持恢复/永久删除）
│   └── Agent 调教（评审后微调行为参数）
│
├── 评审大厅
│   ├── 评审团队选择（1-5 个 Agent）
│   ├── 多角色并行评审（各 Agent 独立分析）
│   ├── 评审报告展示（评分 + 观点 + 共识/争议 + 建议）
│   ├── 对比视图（同一段落不同角色批注对比）
│   ├── 建议采纳追踪
│   └── 一键重新评审
│
├── 聊天室
│   ├── 创建聊天室（从评审结果一键进入 / 手动创建选择 Agent）
│   ├── 多 Agent 对话（@提及自动补全 + 指定 Agent 优先回复）
│   ├── Agent 间互动（自动回应其他 Agent 观点，多 Agent 轮流发言）
│   ├── 动态邀请 Agent（新 Agent 自动打招呼并加入讨论）
│   ├── 聊天室管理（关闭/删除，列表页和详情页均可操作）
│   ├── 引用文档原文
│   └── 聊天历史
│
└── 用户系统（v0.2.0 已隐藏登录注册）
    ├── 自动匿名体验用户（首次访问自动创建，无需登录）
    ├── 新手引导
    ├── 个人设置（LLM API 配置）
    └── 数据管理（导出/清除本地数据）
```

### 2.2 模块职责与边界

| 模块 | 核心职责 | 输入 | 输出 | 边界约束 |
|------|---------|------|------|---------|
| 文档中心 | 文档的存储、解析、生命周期管理 | 用户上传的文件 | 结构化文档数据 | 不做内容编辑，只负责读取与展示 |
| Agent 工坊 | Agent 角色的创建、管理、共享 | 用户描述 / 模板参数 | 可执行的 Agent 配置 | 不直接执行评审，只提供角色定义 |
| 评审大厅 | 调度 Agent 对文档进行评审并生成报告 | 文档 + Agent 团队 | 评审报告（评分/建议/争议） | 单次评审 1-5 个 Agent |
| 聊天室 | 用户与 Agent、Agent 与 Agent 的实时对话 | 评审上下文 + 用户消息 | 对话消息 + 辩论总结 | 聊天室不修改文档，只产出讨论结论 |
| 用户系统 | 身份认证、权限管理 | 注册/登录信息 | 用户身份 Token | 所有模块依赖此模块鉴权 |

### 2.3 模块间依赖关系

```
用户系统 ──────→ 所有模块（认证鉴权）

文档中心 ──────→ 评审大厅（提供文档数据）
Agent工坊 ─────→ 评审大厅（提供 Agent 配置）
评审大厅 ──────→ 聊天室（提供评审上下文、争议点）
Agent工坊 ─────→ 聊天室（提供可邀请的 Agent）

聊天室 ────×──→ 评审大厅（辩论总结可更新建议，但异步松耦合）
```

关键设计原则：
- 模块间**单向依赖**，避免循环调用
- 聊天室与评审大厅之间是**松耦合**关系（通过事件通知更新）
- AI 引擎层作为**横切关注点**，被评审大厅和聊天室共同调用

## 3. 核心用户流程

### 3.1 首次使用流程（新手引导）

```
注册/登录
    │
    ▼
引导页：「让我们创建你的第一个评审角色」
    │
    ▼
对话式创建 Agent（AI 引导 2-3 轮）
    │
    ▼
系统提供一份示例文档
    │
    ▼
用刚创建的 Agent 发起一次评审
    │
    ▼
展示评审报告 → 引导查看建议
    │
    ▼
引导完成 → 进入主界面
```

### 3.2 主线流程（文档评审）

```
上传文档 → 选择评审团队 → 发起评审 → 查看报告
    │                                │
    │                    ┌───────────┴───────────┐
    │                    │                       │
    │               采纳建议                  有疑问/争议
    │                    │                       │
    │               导出报告              进入聊天室辩论
    │                    │                       │
    │                完成                    继续讨论
    │                                            │
    │                                     需要新视角？
    │                                     │         │
    │                                  邀请Agent  生成同事
    │                                            │
    │                                     生成辩论总结
    │                                            │
    └────────────────────────────────→ 优化文档 → 重新评审
```

### 3.3 Agent 创建流程

```
进入 Agent 工坊
    │
    ├── 快速路径：选择预设模板 → 一键使用 → 可编辑
    │
    └── 自定义路径：点击"创建新Agent"
            │
            ▼
        AI 对话引导（1-5 轮）
            │
            ▼
        预览 Agent 卡片
            │
            ├── 满意 → 保存
            └── 调整 → 继续对话
                    │
                    ▼
               保存成功 → 推荐同事 Agent
```

## 4. 数据流

### 4.1 核心数据实体关系

```
User (1) ──────→ (N) Document
User (1) ──────→ (N) Agent
User (1) ──────→ (N) Review
User (1) ──────→ (N) ChatRoom

Document (1) ──→ (N) Review
Agent (N) ←─────→ (N) Review     (多对多，通过 ReviewAgent 中间表)

Review (1) ────→ (0..1) ChatRoom
Document (1) ──→ (0..N) ChatRoom

ChatRoom (1) ──→ (N) ChatMessage
Agent (N) ←─────→ (N) ChatRoom   (多对多，通过 ChatParticipant 中间表)
```

### 4.2 核心数据流转路径

```
路径 1：文档评审流
  用户上传文件 → 解析为结构化数据 → 存储
  → 用户选择 Agent → 组装 system prompt
  → 并行调用 LLM → 各 Agent 输出评审
  → 汇总生成报告 → 展示给用户

路径 2：Agent 创建流
  用户描述 → AI 对话引导 → 推断角色参数
  → 生成 system prompt → 存储 Agent 配置
  → 推荐同事 Agent → 展示推荐

路径 3：聊天辩论流
  用户选择争议点 → 创建聊天室（携带评审上下文）
  → 用户发言 → 根据 Agent 角色生成回复
  → Agent 间自动互动 → 持续对话
  → 用户触发总结 → AI 汇总关键观点 → 存储

路径 4：导出流
  评审报告 + 辩论总结 → 组装报告模板
  → 渲染为 PDF/Markdown → 用户下载
```

### 4.3 关键数据实体

| 实体 | 核心字段 | 数据量预估 | 生命周期 |
|------|---------|-----------|---------|
| User | id, email, name, avatar | MVP: 500 | 永久 |
| Document | id, ownerId, title, rawContent, structuredContent, keywords, summary | MVP: 5000 | 用户可删除 |
| Agent | id, ownerId, name, personality, expertise, behavior, systemPrompt | MVP: 4000 | 用户可删除 |
| AgentTemplate | id, name, personality, expertise, behavior | 8 个预设 | 系统管理 |
| Review | id, documentId, agentIds, overallScore, agentReviews, summary | MVP: 10000 | 跟随文档 |
| ChatRoom | id, reviewId, documentId, participants, context, summary | MVP: 2500 | 跟随文档 |
| ChatMessage | id, roomId, senderType, senderId, content, quotes | MVP: 50000 | 跟随聊天室 |

## 5. [教研版] 专属架构扩展

### 5.1 教研角色体系

```
教研评审团（12 个预设角色）
│
├── 教研老师（6 个维度专家）
│   ├── 周老师 📐 — 课程设计（教学架构完整性、环节衔接）
│   ├── 林老师 🔗 — 知识链（知识衔接、递进关系、迁移路径）
│   ├── 陈老师 🎯 — 教学目标（三维目标、可测量性、达成路径）
│   ├── 王老师 📌 — 课程重点（重点突出度、时间分配合理性）
│   ├── 张老师 🧩 — 课程难点（突破策略、认知阶梯设计）
│   └── 李老师 📊 — 学习梯度（坡度设计、分层教学策略）
│
├── 学生视角（3 个年级段）
│   ├── 小明 🎒 — 小学生（趣味性、直观理解、注意力）
│   ├── 小芳 📓 — 初中生（理解难度、学习节奏、作业负担）
│   └── 小杰 🎓 — 高中生（思维深度、效率、考试关联性）
│
└── 家长视角（3 种教育理念）
    ├── 刘妈妈 📈 — 关心成绩型（目标明确性、效果可衡量）
    ├── 赵爸爸 🌱 — 关注素质型（思维培养、探索精神）
    └── 孙阿姨 ☕ — 放手型（学习体验、心理负担）
```

### 5.2 六维度评审模型

| 维度 | 评审内容 | 关键指标 |
|------|---------|---------|
| 课程设计 | 教学设计完整性、环节编排、时间分配 | 各环节占比是否合理 |
| 知识链 | 前后知识衔接、递进关系、迁移路径 | 是否有知识断裂或跳跃 |
| 教学目标 | 三维目标明确性、可测量性、达成路径 | 每个环节是否服务于目标 |
| 课程重点 | 重点是否突出、时间是否倾斜 | 核心知识的呈现方式 |
| 课程难点 | 难点识别准确性、突破策略合理性 | 认知阶梯是否平缓 |
| 学习梯度 | 认知坡度、分层设计、弹性节奏 | 不同层次学生的适应性 |

### 5.3 教研案智能解析

```
上传教研案文件（PDF/Word/MD/TXT）
    │
    ▼
文档解析（提取原文 + 分段）
    │
    ▼
智能字段提取（正则匹配关键结构）
    ├── 基本信息：课题、学科、年级、课时
    ├── 三维目标：知识与技能 / 过程与方法 / 情感态度与价值观
    ├── 重难点：教学重点、教学难点
    ├── 教学过程：导入 → 新授 → 练习 → 小结 → 作业
    └── 辅助内容：板书设计、教学反思
    │
    ▼
结构化数据存入 Document.teaching_plan
    │
    ▼
传入评审引擎，提升评分精准度
```
