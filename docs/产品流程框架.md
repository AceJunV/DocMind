# 📋 DocMind — 多角色 Agent 文档评审平台 · 产品流程框架

> 版本：v1.0 | 日期：2026-04-20

---

## 一、产品全景

### 1.1 产品定位

**一句话描述**：用户上传文档，创建/选择不同身份的 AI Agent 组成评审团队，获得多视角评价，并可在聊天室中与 Agent 深度辩论。

**核心价值**：将「多角色评审」从高成本的人工协作，变为零等待的 AI 即时体验。

### 1.2 产品架构总览

```
┌─────────────────────────────────────────────────┐
│                   DocMind 平台                    │
├──────────┬──────────┬──────────┬─────────────────┤
│  文档中心  │ Agent工坊 │ 评审大厅  │    聊天室       │
│          │          │          │                 │
│ · 上传    │ · 创建    │ · 选团队  │ · 单Agent对话   │
│ · 管理    │ · 调教    │ · 看评价  │ · 多Agent辩论   │
│ · 历史    │ · 模板库  │ · 对比视图 │ · 邀请加入     │
│ · 导出    │ · 共享    │ · 优化建议 │ · 历史记录     │
└──────────┴──────────┴──────────┴─────────────────┘
         │              │              │
         └──────────────┼──────────────┘
                        ▼
              ┌─────────────────┐
```

## 二、核心用户旅程（Main Journey）

```
用户旅程主线：

注册/登录 → 创建/选择Agent → 上传文档 → 发起评审 → 查看多角色评价
    │                                          │
    │              ┌───────────────────────────┘
    │              ▼
    │         对评价满意？
    │         ├── 是 → 导出/采纳建议 → 结束
    │         └── 否 → 进入聊天室 → 与Agent辩论 → 优化文档 → 重新评审
    │                      │
    │                      ▼
    │               辩论中需要新视角？
    │               └── 邀请新Agent加入 → 继续讨论
    │
    └── 首次使用 → 引导创建第一个自定义Agent
```

## 三、四大核心模块详解

### 模块一：文档中心 📄

**职责**：文档的上传、管理、版本追踪

#### 流程

```
上传文档 → 解析内容 → 结构化存储 → 展示文档信息
   │
   ├── 支持格式：PDF / Word / Markdown / TXT
   ├── 文档大小限制：20MB
   └── 自动提取：标题、段落结构、关键词、摘要
```

#### 核心页面/功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 文档上传 | 拖拽或点击上传，自动解析 | P0 |
| 文档列表 | 按时间/名称排列，显示评审状态 | P0 |
| 文档详情 | 展示文档内容 + 历史评审记录 | P0 |
| 版本管理 | 同一文档多版本对比 | P2 |
| 文档导出 | 导出评审报告（PDF/Markdown） | P1 |

### 模块二：Agent 工坊 🎭

**职责**：Agent 的创建、调教、管理、共享

#### 流程 A — 对话式创建 Agent（核心体验）

```
用户点击"创建新Agent"
        │
        ▼
┌─────────────────────────┐
│  AI引导对话开始            │
│  "你想创建什么样的角色？"    │
└────────────┬────────────┘
             │
             ▼
      用户描述角色（1-3句）
      例："一个严格的技术Leader，注重代码规范"
             │
             ▼
┌─────────────────────────┐
│  AI补充完善角色特征          │
│  · 自动推断：专业领域/性格    │
│  · 生成：名字/头像/口头禅    │
│  · 展示：Agent 预览卡片      │
└────────────┬────────────┘
             │
             ▼
      用户满意？
      ├── 是 → 保存到我的Agent库
      └── 否 → 继续对话调整（最多5轮）
               · "说话再毒舌一点"
               · "加上对性能的关注"
               · "换个头像风格"
```

#### 流程 B — 同事 Agent 推荐

```
场景触发点：
┌────────────────────────────────────┐
│ 1. 创建Agent完成后 → 推荐"搭档角色"   │
│ 2. 发起评审选Agent时 → 推荐互补角色    │
│ 3. 聊天室中 → 一键生成"同事Agent"     │
└────────────┬───────────────────────┘
             │
             ▼
    AI分析当前角色/文档上下文
             │
             ▼
    生成推荐列表（2-3个）
    例：你创建了"技术Leader" → 推荐"产品经理""UX设计师"
             │
             ▼
    用户选择 → 快速创建（预填大部分参数）→ 微调 → 保存
```

#### Agent 数据模型

```yaml
Agent 身份卡：
  id: "agent_xxx"
  owner: "user_xxx"
  
  # 基础信息
  name: "老张"
  avatar: "https://..."          # AI生成或选择
  tagline: "毒舌但专业的技术Leader"
  
  # 性格参数
  personality:
    tone: "direct"               # 温和/直接/毒舌/鼓励
    strictness: 4                # 严格度 1-5
    cooperation: "collaborative"  # 合作型/对抗型/互补型
  
  # 专业能力
  expertise:
    domain: ["技术", "架构"]       # 领域标签
    focus: ["代码规范", "性能", "可维护性"]  # 关注重点
    depth: "senior"               # junior/mid/senior/expert
  
  # 行为特征
  behavior:
    catchphrase: "这代码写得...我看看"   # 口头禅
    facing_challenge: "evidence_based"   # 面对质疑：坚持/看证据/妥协
    review_style: "detail_oriented"     # 宏观/细节/平衡
  
  # 来源
  source: "custom"               # custom/template/community
  is_public: false               # 是否共享到社区
```

#### 核心页面/功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 对话式创建 | 与AI对话3-5轮生成Agent | P0 |
| 我的Agent库 | 查看/编辑/删除已创建的Agent | P0 |
| Agent模板库 | 预设优质模板，一键使用 | P0 |
| 同事推荐 | 基于上下文推荐互补角色 | P1 |
| Agent调教 | 评审后微调Agent行为参数 | P1 |
| 社区共享 | 发布/使用他人共享的Agent | P2 |

### 模块三：评审大厅 🏛️

**职责**：组织多角色对文档进行评审，展示评价结果

#### 核心流程

```
选择文档 → 选择评审团队（1-5个Agent）→ 发起评审
                                            │
                                            ▼
                                   ┌─────────────────┐
                                   │  各Agent并行分析   │
                                   │  · 基于角色参数    │
                                   │  · 结合文档内容    │
                                   │  · 给出独立评价    │
                                   └────────┬────────┘
                                            │
                                            ▼
                                   展示评审结果面板
                                   ┌─────────────────────┐
                                   │  📊 总体评分          │
                                   │  👤 Agent-A 说：...   │
                                   │  👤 Agent-B 说：...   │
                                   │  👤 Agent-C 说：...   │
                                   │                      │
                                   │  🔥 共识点 / ⚡ 争议点  │
                                   │  💡 优化建议（优先排序） │
                                   └─────────────────────┘
                                            │
                                            ▼
                                   用户操作：
                                   ├── ✅ 采纳建议 → 标记已采纳
                                   ├── ❓ 有疑问 → 发起聊天室辩论
                                   └── 🔄 重新评审（修改文档后）
```

#### 评审结果展示设计

```
┌──────────────────────────────────────────┐
│  📄 《xxx文档》评审报告                     │
│                                          │
│  综合评分：★★★★☆ 4.2/5                    │
│                                          │
│  ┌──────┬──────┬──────┬──────┐            │
│  │ 结构  │ 逻辑  │ 表达  │ 可行性│           │
│  │ 4.5  │ 4.0  │ 3.8  │ 4.5  │           │
│  └──────┴──────┴──────┴──────┘            │
│                                          │
│  🤝 三方共识：                             │
│  · 文档结构清晰，逻辑主线完整               │
│  · 第三章的数据支撑不够                     │
│                                          │
│  ⚡ 角色争议：                             │
│  · 技术Leader认为方案可行                  │
│  · 产品经理认为用户价值不明确               │
│  → [进入聊天室辩论]                        │
│                                          │
│  💡 优化建议 TOP 5：                       │
│  1. 补充第三章的数据来源     [高优先]       │
│  2. 增加用户场景描述         [高优先]       │
│  3. 简化技术实现方案描述     [中优先]       │
│  4. 补充风险评估            [中优先]       │
│  5. 优化摘要的表达           [低优先]       │
└──────────────────────────────────────────┘
```

#### 核心页面/功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 选择评审团队 | 从Agent库中选1-5个Agent | P0 |
| 多角色并行评审 | 各Agent独立给出评价 | P0 |
| 评审报告展示 | 评分+观点+共识+争议+建议 | P0 |
| 对比视图 | 同一段落的不同角色批注对比 | P1 |
| 建议采纳追踪 | 标记哪些建议被采纳 | P1 |
| 一键重新评审 | 修改后快速重评 | P1 |

### 模块四：聊天室 💬

**职责**：用户与Agent、Agent与Agent之间的深度对话和辩论

#### 场景 A — 单 Agent 深入对话

```
触发：用户点击评审报告中的「追问」
流程：
  用户提问 → Agent基于角色身份回答 → 持续对话
  · Agent会引用文档原文作为依据
  · Agent会根据自身性格给出态度（坚持/妥协/反思）
```

#### 场景 B — 多 Agent 辩论（核心亮点）

```
触发：用户点击「进入聊天室辩论」
流程：

┌─────────────────────────────────────────┐
│  💬 评审辩论室                            │
│                                         │
│  👤 用户：第三章的方案到底可不可行？         │
│                                         │
│  🧑‍💻 技术Leader：方案技术上是可行的，        │
│     但性能开销需要评估                     │
│                                         │
│  📋 产品经理：我不同意，用户不会为这个        │
│     功能买单，ROI太低                      │
│                                         │
│  🎨 UX设计师：从体验角度，这个方案会让        │
│     操作流程变复杂                         │
│                                         │
│  🧑‍💻 技术Leader → 📋 产品经理：             │
│     但如果优化交互，用户价值是可以实现的       │
│                                         │
│  👤 用户：[输入回复...]                    │
│                                         │
│  [邀请Agent加入]  [结束辩论] [生成总结]     │
└─────────────────────────────────────────┘
```

#### 聊天室核心交互

```
聊天室内可用操作：

1. @某Agent 直接提问     → 该Agent优先回复
2. 邀请新Agent加入       → 从Agent库选择或一键生成
3. 引用文档原文          → 所有Agent基于引用内容讨论
4. Agent间自动互动       → 不同角色会对其他Agent的观点做出反应
5. 生成辩论总结          → AI提炼关键分歧点和共识
6. 结束辩论 → 回到评审报告  → 更新建议
```

#### 核心页面/功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 创建聊天室 | 从评审结果一键进入 | P0 |
| 多Agent对话 | 支持多角色同时在场 | P0 |
| Agent间互动 | Agent自动回应其他Agent | P0 |
| 邀请Agent | 动态添加新Agent | P1 |
| 引用文档 | 引用原文作为讨论依据 | P1 |
| 辩论总结 | AI自动提炼关键结论 | P1 |
| 聊天历史 | 保存历史辩论记录 | P2 |

## 五、MVP 优先级排序（RICE 模型）

| 序号 | 功能模块 | Reach(覆盖面) | Impact(影响力) | Confidence(信心) | Effort(工作量) | 优先级 |
|------|---------|:---:|:---:|:---:|:---:|:---:|
| 1 | 文档上传与解析 | 10 | 3 | 90% | 2周 | **P0** |
| 2 | 预设Agent模板库（5-8个） | 10 | 3 | 85% | 1周 | **P0** |
| 3 | 多角色并行评审 | 10 | 4 | 80% | 3周 | **P0** |
| 4 | 评审报告展示 | 10 | 4 | 85% | 2周 | **P0** |
| 5 | 对话式创建Agent | 8 | 3 | 75% | 3周 | **P1** |
| 6 | 多Agent聊天室 | 8 | 4 | 70% | 3周 | **P1** |
| 7 | 同事Agent推荐 | 6 | 3 | 70% | 2周 | **P1** |
| 8 | Agent间自动互动 | 6 | 3 | 65% | 2周 | **P1** |
| 9 | Agent社区共享 | 4 | 2 | 60% | 3周 | **P2** |
| 10 | 评审报告导出 | 5 | 2 | 80% | 1周 | **P2** |

### 建议迭代节奏

```
MVP（v0.1）— 6周：
  文档上传 + 预设Agent + 多角色评审 + 评审报告
  
v0.2 — 4周：
  对话式创建Agent + 多Agent聊天室
  
v0.3 — 3周：
  同事Agent推荐 + Agent间互动 + 辩论总结
  
v1.0 — 3周：
  社区共享 + 导出 + 优化打磨
```

## 六、关键设计原则

| 原则 | 说明 |
|------|------|
| 🎭 角色一致性 | Agent在任何场景都严格遵循设定的身份和性格 |
| 💬 对话真实感 | Agent间辩论要有"碰撞感"，不是各说各话 |
| ⚡ 即时反馈 | 评审结果流式输出，不让用户干等 |
| 🎯 建议可执行 | 每条建议必须具体到"改哪里、怎么改" |
| 🔧 用户可控 | 用户可随时调整Agent、中断辩论、重新评审 |
